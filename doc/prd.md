# AI展示面大师 — 产品需求文档（PRD）

> 文档版本：V2.0（基于实际项目复盘重制）| 日期：2026年9月6日
> 
> **项目背景**：本项目已实际跑通MVP验证——2周营收近2万元，100+付费用户，付费转化率30%+。本PRD基于真实市场反馈重新提炼，而非停留在假设阶段的产品构想。


## 一、产品概述

### 1.1 产品缘起（来自真实痛点）

**创始人的身份：** 北邮硕士，前360/百度产品经理，年薪60万，但完全不懂代码——是一个典型的“有场景洞察力但无技术实现能力”的产品经理。

**最原始的需求：** 创始人和大多数普通男生一样——手机相册翻来翻去全是工作截图和随手拍，没有几张能放在交友软件上的好照片。在Soul、牵手、青藤等平台上，异性第一次认识你，靠的就是头像和主页里的照片，但大多数男生不会拍、不知道怎么拍、也没有合适的照片。

这不是少数人的问题，它是一个真实、普遍且**有人愿意付钱解决的痛点**。

### 1.2 产品定位

**AI展示面大师**是一款面向社交软件用户的轻量级AI工具，核心价值是：**用户上传一张自拍 + 一张喜欢的穿搭/场景参考图 + 一段提示词，AI生成一张更有氛围感的社交展示照片。**

它不是把用户变成明星或换脸成另一个人，而是在**不改变五官**的前提下，优化穿搭、光线、环境，让普通男生也能拥有“能让人停下来多看一眼”的照片。

### 1.3 核心理念

> **"先让用户跑通一次，再谈留存和复购。"**

产品设计的第一原则是**极简路径**——用户付款后，在最短时间内完成第一次生成，并知道下一步该做什么。功能多不等于好产品，尤其对不熟悉AI的普通用户来说，功能越多，越不知道从哪里开始。


## 二、目标用户

### 2.1 用户画像

| 属性 | 描述 |
|------|------|
| **年龄** | 20-35岁 |
| **性别** | 以男性为主（可扩展至女性） |
| **身份** | 上班族、大学生、普通单身青年 |
| **核心场景** | 使用交友软件（Soul、牵手、青藤、Tinder等），但缺乏高质量个人照片 |
| **行为特征** | 平时不怎么拍照，手机相册缺乏可用照片；不熟悉AI工具，不愿研究复杂平台 |
| **消费意愿** | 愿意为"改善第一印象"付费，但对高价敏感（入门价69元） |

### 2.2 用户痛点

1. **无图可用**：相册翻五年找不出几张能用的照片
2. **不会拍照**：不知道什么风格、场景、穿搭更适合自己
3. **不想学AI**：对教程、token、复杂平台没有耐心，只想看到结果
4. **预算有限**：线下约拍（租车+摄影+修图）成本太高（数千元），且风格过时


## 三、市场验证（已发生数据）

### 3.1 竞争品分析

**同行产品（参考对象）：** 售价399元的教程 + RunningHub（AIGC聚合平台）。用户购买后还需额外购买token，且要自己研究如何操作。

**发现的问题：**
- 399元不包含生图token，用户需另行充值
- 平台功能大而全，但对只想"做几张照片"的普通用户来说太复杂
- 用户付款后真正的难题（怎么选图、怎么操作、生成失败怎么办）仍然留给了用户自己

### 3.2 已验证的市场数据

| 指标 | 数据 |
|------|------|
| 产品单价 | 69元（入门） |
| 销售量 | 100+单 |
| 付费转化率 | 30%+（从199元降价后，3个咨询成交1个） |
| 续充值比例 | 约1/3购买用户继续充值，单笔约50元 |
| 单次生成成本 | 约1元/次（50元可生成约50次） |
| 2周总营收 | 近2万元（69元销售 + 平台充值 + 8,000元代运营单） |
| 高客单案例 | 1单8,000元（3个月抖音代运营） |


## 四、核心功能

### 4.1 MVP功能范围（已验证）

**核心逻辑：越简单越好。不做大而全的AIGC平台，只把"展示面"这一个功能抽出来。**

| 功能 | 说明 | 状态 |
|------|------|------|
| 照片上传 | 用户上传一张人脸图（自拍） | ✅ 已实现 |
| 参考图上传 | 用户上传喜欢的穿搭/场景/风格参考图 | ✅ 已实现 |
| 提示词输入 | 用户可输入或选择预设提示词 | ✅ 已实现 |
| AI生成照片 | 基于人脸图+参考图+提示词生成展示面照片 | ✅ 已实现 |
| 免费试用 | 新用户可免费生成1次体验 | ✅ 已实现 |
| 按次付费充值 | 最低50元起充，约1元/次 | ✅ 已实现 |
| 微信/网页端 | 手机和电脑浏览器均可打开使用 | ✅ 已实现 |

### 4.2 V2.0规划功能（基于复盘调整）

| 功能 | 优先级 | 说明 |
|------|--------|------|
| **小程序版本** | P0（迁移中） | 从微信个人号承接转为小程序自助，减少人工干预 |
| **风格模板库** | P1 | 预设10+种展示面风格（咖啡厅、海边、健身房、城市街景等） |
| **一键生成多张** | P1 | 一次生成6-12张不同风格组合 |
| **文案自动生成** | P2 | 根据用户信息生成个人简介文案 |
| **多平台适配** | P2 | 一键导出适配Soul/抖音/小红书/朋友圈的尺寸 |
| **老用户权益补发** | P0 | 已付69元用户补发一定周期内的免费生成次数 |

### 4.3 明确不做的功能（V1阶段）

以下功能在MVP阶段**刻意不做**，以保持产品轻量：

- ❌ 监控优秀展示面 + 一键复刻（会做重产品）
- ❌ 人工代做展示面（每单100-200元，但交付极重，沟通成本高）
- ❌ 大而全的AIGC平台（用户不需要来参观你会多少模型）


## 五、技术方案

### 5.1 架构概览

| 层级 | 方案 |
|------|------|
| **前端** | 响应式Web页面（兼容手机+电脑浏览器）→ 后续迁移至小程序 |
| **AI图像生成** | 调用第三方AIGC平台API（非自研模型，初期无需重投入） |
| **用户系统** | 手机号/微信登录 |
| **支付** | 微信支付 |
| **存储** | 云存储（用户上传图 + 生成结果） |

### 5.2 关键决策

- **不自研模型，先接API**：验证阶段不需要自己训练模型，接入成熟平台即可快速验证需求
- **Token消耗模式**：用户充值后按生成次数扣费，单次成本可控（约1元/次）
- **平台化第一步**：从Web迁移至小程序，缩短用户使用路径


## 六、商业模式

### 6.1 收入结构（两层模型）

| 层级 | 产品 | 价格 | 说明 |
|------|------|------|------|
| **第一层：入门门槛** | 教程 + 工具使用权 | **69元** | 降低用户决策门槛，转化率从~5%提升至30%+ |
| **第二层：持续消耗** | 平台充值 | 50元起充（≈50次） | 约1/3用户续充，形成持续收入 |
| **高客单延伸** | 代运营服务 | 8,000元/3个月 | 已验证有用户愿意为"全托管"服务付更高价 |

### 6.2 定价策略的核心洞察

> **用户付费意愿不取决于"东西值不值199"，而取决于"付完钱离想要的结果还有多远"。**

- 199元（教程+工具）→ 转化率极低：用户还要自己研究平台、买token、承担失败风险
- 69元（入门）+ 平台自助使用 → 转化率30%+：用户路径短，第一次生成快

### 6.3 为什么不做人工代做？

市面上人工代做展示面收费100-200元/张，看起来单价更高，但存在严重问题：

- **AI生图是"抽卡"** ：不是每次生成都一次到位，需要多轮
- **客户预期管理难**：用户觉得"AI应该一次完美"，不满意就要反复改
- **沟通成本极高**：每一张"不像、场景不对、衣服换一下、表情不好"都需要大量沟通

**结论**：人工代做会把一个轻交付做成重人工项目，天花板更低。工具模式让用户自己参与生成、自己控制，才有可能放大。


## 七、用户路径

### 7.1 当前路径（Web端）

```
抖音/小红书看到内容 → 微信加好友咨询 → 支付69元 → 获取教程+工具链接 → 免费体验1次 → 充值继续使用
```

⚠️ **瓶颈**：所有用户先加个人微信，人工承接压力大，已出现6个微信号被封/降权。

### 7.2 优化后路径（V2.0）

```
抖音/小红书看到内容 → 进入小程序/网站 → 免费试用1次 → 支付69元解锁全部功能 → 按需充值继续生成 → 高客单用户主动联系人工
```

✅ **改进点**：低客单用户走自助短链路，不需要加个人微信；私域只留给需要深度沟通的高客单用户。


## 八、关键风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| **微信风控/封号** | 引流承接中断，6个号已被影响 | 迁移至小程序，低客单走自助路径，减少人工导流 |
| **AI生成不像本人** | 用户不满意，退款/差评 | 产品说明中明确"优化穿搭、光线、环境，不改变五官"；免费试用让用户先体验再付费 |
| **伦理与真实性** | 伪造身份用于欺诈 | 明确禁止伪造身份、冒充他人；仅用于个人展示面优化 |
| **算力成本不可控** | 单用户多次生成导致成本超支 | 按次计费模式，用户充值后消耗，成本与收入绑定 |
| **竞品跟进** | 同类工具快速出现 | 核心壁垒不在工具本身，而在"获客链路+产品迭代速度+用户社群" |

## 十、给产品经理的复盘总结

**这个项目用两周跑通了完整的AI变现链路，核心经验有五条：**

1. **从自己的真问题出发，不要从"AI能做什么"出发。** 创始人自己就是目标用户，对痛点的体感是第一手判断依据。

2. **先花钱买一次同行的产品。** 公开内容只能看到表面，交付才能让你看见结构——用户付款后到底拿到了什么、卡在哪里。

3. **AI编程最有价值的是快速验证，而不是做一个功能齐全的作品。** 第一版只要跑通"有人看见→有人付款→有人完成第一次生成"这一条链路就够了。

4. **定价的本质是"缩短用户到结果的距离"。** 从199元降到69元，不是简单的价格战，而是降低了用户的决策成本和操作门槛。

5. **获客、承接、交付必须一起设计。** 内容爆了只是入口，不代表业务跑通。低客单走自助短链路，高客单再进私域，项目要在规则内能重复跑，才有继续做的价值。
